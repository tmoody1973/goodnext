# 002 Use the GoodNext name in code and copy; leave document filenames alone for now

**Decision** — The product is GoodNext. Code, the README, and resident-facing text say GoodNext. The twenty planning documents keep their "FoodShare-Bridge" filenames and internal wording until a separate documentation pass.

**Why this came up** — Tarik named the product GoodNext on September 8, 2026, after the planning documents were written under the working title. A rename touches every cross-link between documents and the checksums in the deliverables package.

**Options**
- *Rename only code and copy now.* Cost: two names coexist for a while, and a reader of the docs has to be told.
- *Rename everything now.* Cost: twenty files, dozens of links, a broken deliverables manifest, and time taken from the build with six days left.

**What we chose and why** — Rename code and copy only. Joint call. The README states the mapping in one line, so nobody is confused, and the documents stay stable references for the hackathon submission.

**What we gave up** — Consistency. Until the docs pass, the PRD and the app disagree on the name.

**How we'll know if this was right** — No one on the project asks "which one is it?" after reading the README, and the docs pass happens after submission without touching code.
